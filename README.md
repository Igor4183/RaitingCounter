# RaitingCounter

RaitingCounter — это C++‑проект для скачивания и парсинга страниц с результатами соревнований по ориентированию, генерацию HTML‑рейтинга.

Проект проходит несколько стадий обработки:

1. чтение `config.json`;
2. скачивание и парсинг страниц в БД;
3. сбор и хранение структурированных данных;
4. генерация HTML‑файлов.

## Что умеет проект

- читает настройки из `config.json`;
- скачивает страницы с результатами соревнований;
- создание и чтение БД;
- парсит HTML и извлекает нужные данные;
- формирует внутреннюю структуру данных по спортсменам и результатам;
- создаёт два HTML‑файла:
  - **debug** — простой вывод для проверки данных;
  - **release** — красивый HTML с UI для просмотра результатов.

## Сборка проекта

### Требования

* CMake 3.20+
* Ninja
* GCC 14 с поддержкой C++20

### Конфигурация

```bash
cmake -S . -B build -G "Ninja Multi-Config" -DCMAKE_C_COMPILER=gcc-14 -DCMAKE_CXX_COMPILER=g++-14
```

### Сборка

Сборка в режиме Debug:

```bash
cmake --build build --config Debug
```

Сборка в режиме Release:

```bash
cmake --build build --config Release
```

## Конфигурация

Проект читает настройки из файла `config.json`.

В конфиге хранятся:

- ссылки на страницы результатов;
- группы, которые нужно обрабатывать;
- тип итогового вывода;
- дополнительные параметры страниц (название, дисциплина, дата, класс и т.д.).

Пример логики конфигурации:

```json
{
  "valid_starts": 6,
  "groups": ["М18"],
  "pages": [
    {
      "id": 1,
      "url": "http://example.com/page.htm",
      "title": "Example Competition",
      "nameTable": "Example_name",
      "discipline": "classic",
      "date": "2026-04-05",
      "class": 1000
    }
  ]
}
```

## Хранение результатов

Для хранения, кэширования и дальнейшего частичного обновления результатов используется SQLite база данных.

Структура таблицы, название которой указано в`config.json`:

#### main_base.db

```sql
CREATE TABLE competition (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    athlete_id INTEGER,
    birth_year INTEGER,
    club TEXT,
    group_name TEXT,
    total_time INTEGER,
    place INTEGER,
    status TEXT,
    FOREIGN KEY (athlete_id) REFERENCES athlete(athlete_id) ON DELETE SET NULL
);
```

>`status` принимает значения от -2 до 1:
>- `valid` = 1,
>- `outOfCompetition` = 0, // в/к
>- `removed` = -1, // cнят
>- `undefined` = -2.

**Таблица athlete(общая база спортсменов):**
```sql
CREATE TABLE athlete (
    athlete_id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT, 
    birth_year INTEGER, 
    category TEXT
);
```
> В случае проблем с работой БД можно раскомментировать вызов функции parse в main.cpp и закомментировать две верхние строки. Тогда программа будет работать без использования базы данных.

## Выходные файлы

Проект создаёт два HTML‑файла:

- **debug HTML** — для быстрой проверки корректности парсинга;
- **release HTML** — для удобного просмотра результатов с оформлением.

## Структура проекта

Проект состоит из нескольких модулей:

- `config` — чтение и обработка `config.json`;
- `parser/` — скачивание и парсинг HTML с последующим сохраниением таблицы БД в `main_base.db`;
- `model` — структуры данных;
- `generator/` — генерация HTML‑страниц;
- `u32string` — работа с Unicode/кириллицей;
- `main` — точка входа.
